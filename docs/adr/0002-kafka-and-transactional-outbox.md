# Kafka и transactional outbox

`users` и `games` сохраняют изменение данных и запись в outbox в одной транзакции PostgreSQL. Публикатор отмечает событие отправленным после подтверждения Kafka. Если процесс остановился между подтверждением и отметкой, он отправит событие повторно. Потребители обрабатывают повтор по стабильному `event_id`.

Kafka доставляет события независимым потребителям. Например, событие бана меняет записи в `games` и запускает уведомление в `telegram`. `telegram` сохраняет задание доставки с уникальным ключом до подтверждения обработки события Kafka. Повторы временных ошибок Telegram Bot API выполняются из базы заданий. Если API принял сообщение, но ответ потерялся, повтор запроса может создать дубль у получателя.
