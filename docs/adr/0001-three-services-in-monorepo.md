# Три сервиса в монорепозитории

Разделяем приложение на `users`, `games` и `telegram` по владению данными и причинам для изменений. Учётные записи и права принадлежат `users`, правила клуба и составы принадлежат `games`, взаимодействие с Telegram и повторы доставки принадлежат `telegram`. Раздельный запуск позволяет обслуживать игры через REST при сбоях Telegram Bot API.

Код сервисов, контракты, миграции и локальный Docker Compose храним в одном репозитории. Изменение межсервисного контракта и его вызовов можно проверить одним PR. Сервисы общаются по gRPC и через Kafka, а внешний REST публикуют через Nginx на одном адресе.
