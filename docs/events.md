# События Kafka

`users` и `games` публикуют события через transactional outbox по [ADR 0002](adr/0002-kafka-and-transactional-outbox.md). Публикация начинается на этапе 15. На этапе 17 `telegram` начинает доставлять уведомления, на этапе 18 `games` использует события для обработки явки и дисциплины.

## Топики и формат

| Топик | Издатель | Kafka key |
| --- | --- | --- |
| `volleybot.users.events.v1` | `users` | `user_id` |
| `volleybot.games.events.v1` | `games` | `game_id` для игры, состава и записи, `series_id` для конфликта генерации серии |

Значение сообщения — JSON в UTF-8. В конверте обязательны `event_id` (непрозрачная строка, неизменная при повторной доставке), `event_type`, `schema_version` (целое, сейчас 1), `occurred_at` (RFC 3339 в UTC), `aggregate_id` (совпадает с Kafka key) и `data` (объект по таблице ниже). Все идентификаторы в `data` — строки. Поля `starts_at` и `ends_at` — моменты в RFC 3339. `ends_at: null` у бана означает бессрочный бан. Массивы идентификаторов получателей формируются сервисом-владельцем на момент события. Контакты и секреты в события не передаются. `telegram` получает актуальные настройки и адрес доставки через `users`.

```json
{
  "event_id": "event-35eac2",
  "event_type": "registration.promoted",
  "schema_version": 1,
  "occurred_at": "2026-12-01T16:30:00Z",
  "aggregate_id": "game-105",
  "data": {
    "game_id": "game-105",
    "registration_id": "reg-821",
    "user_id": "user-45"
  }
}
```

## Каталог

Все перечисленные поля `data` обязательны.

| Событие | Поля `data` | Кто обрабатывает |
| --- | --- | --- |
| `user.banned` | `user_id`, `ban_id`, `reason`, `starts_at`, `ends_at` | `games` отменяет записи на ещё не начавшиеся игры в период бана. `telegram` готовит уведомление пользователю. |
| `user.unbanned` | `user_id`, `ban_id` | `telegram` готовит уведомление о снятии бана. Событие означает ручное снятие, в том числе ранее выданного автобана. |
| `game.updated` | `game_id`, `changed_fields`, `recipient_user_ids` | `telegram` уведомляет записавшихся при изменении времени, зала или стоимости. `changed_fields` — массив из `starts_at`, `ends_at`, `hall_id`, `price_kopecks`. |
| `game.cancelled` | `game_id`, `recipient_user_ids` | `telegram` уведомляет записавшихся. Отмена серии выпускает одно событие на каждую будущую отменённую игру. |
| `series.conflict` | `series_id`, `owner_id`, `hall_id`, `starts_at`, `ends_at`, `conflicting_game_id` | `telegram` уведомляет владельца о пропущенной игре. |
| `registration.cancelled` | `game_id`, `registration_id`, `user_id`, `reason`, `late_cancel` | `games` пересчитывает дисциплину при `late_cancel: true`. `reason` — `self`, `ban` или `game_cancelled`. |
| `registration.promoted` | `game_id`, `registration_id`, `user_id` | `telegram` уведомляет о переходе в основной состав. |
| `registration.demoted` | `game_id`, `registration_id`, `user_id` | `telegram` уведомляет о переходе в лист ожидания. |
| `teams.published` | `game_id`, `assignment_version`, `recipient_user_ids` | `telegram` уведомляет основной состав о публикации команд. |
| `teams.reset` | `game_id`, `assignment_version`, `recipient_user_ids` | `telegram` уведомляет игроков о сбросе ранее опубликованной версии при смене формата. |
| `game.finished` | `game_id`, `ends_at` | `games` запускает расчёт неявок, даже если явку никто не отмечал. |
| `attendance.changed` | `game_id`, `registration_id`, `user_id`, `present` | `games` пересчитывает дисциплину после исправления явки у завершённой игры. |

`game.finished` записывается в outbox один раз для каждой неотменённой игры после `ends_at`. Статус игры по-прежнему вычисляется по времени. Для напоминаний `telegram` получает через gRPC текущий основной состав и время игры. Ключ задания напоминания включает `registration_id` и время начала игры. Перед отправкой `telegram` запрашивает кандидата по идентификатору записи и сверяет актуальное время начала со временем в задании.

## Порядок и повторная обработка

- Публикатор сохраняет порядок событий одного ключа при чтении из outbox. Kafka сохраняет этот порядок внутри партиции. Общий порядок между топиками или ключами отсутствует.
- Потребители используют независимые группы Kafka и сохраняют результат обработки и отметку `event_id` атомарно в своей базе. Смещение Kafka подтверждается после сохранения результата. Для уведомлений результат обработки — задание доставки с ключом `(event_id, recipient_user_id)`.
- Обработчик бана учитывает актуальность `ban_id` перед отменой записи, чтобы запоздавшее событие снятого или заменённого бана не отменило запись. Расчёт дисциплины опирается на актуальные записи и отметки явки. Запрос автобана идемпотентен по паре `(user_id, discipline_window_id)`.
- Обработка временных ошибок Telegram Bot API повторяется из сохранённых заданий. При потере ответа после принятия сообщения Telegram возможна повторная доставка пользователю.
- Совместимые дополнения добавляются как необязательные поля. Потребители пропускают неизвестные поля и нерелевантные типы событий. Несовместимые изменения требуют новой версии, а потребители обновляются до переключения публикации.
